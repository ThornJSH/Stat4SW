# Stat4SW 개발계획

구글 시트 + Apps Script(GAS)로 SPSS와 유사한 통계 분석 도구를 만드는 프로젝트의 개발계획입니다.

- 작업용 시트: Stat4SW
- 관리 방식: clasp로 로컬 저장소와 GAS 동기화
- 참고 자료: 기존 「데이터 분석 v1.6」 시트(검증 기준값으로 활용)

---

## 1. 목표와 구조

- 구글 시트(데이터 탭 + 변수정의 탭) + GAS 메뉴 + index.html 결과 화면
- 외부 라이브러리 없이 직접 구현한다. 오픈소스는 알고리즘·정확도 비교용 참조로만 사용한다.
- 분석 함수는 UI와 분리해서 `분석(데이터, 옵션) → 결과 객체` 형태로 만든다.

### 데이터 탭 / 변수정의 탭

| 탭 | 내용 |
| --- | --- |
| 데이터 | 1행 = 변수명, 2행부터 응답 |
| 변수정의 | 변수명, 라벨, 척도(명목/서열/연속), 값 레이블(예: 1=남, 2=여), 결측값 코드 |

### 파일 구성

| 파일 | 역할 |
| --- | --- |
| `Menu.js` | `onOpen()`으로 "Stat4SW 통계분석" 메뉴 생성, 대화상자 호출 |
| `Data.js` | 데이터·변수정의 로드, 결측 처리, 더미 변환 |
| `Distributions.js` | 정규, t, F, χ² 누적확률과 역함수 |
| `Stats_*.js` | 분석별 계산 (분석마다 파일 분리) |
| `Api.js` | `google.script.run`이 호출하는 UI용 함수 |
| `index.html` | 변수 선택, 옵션, 결과표 출력 |

## 2. 개발 단계

### 0단계 기반
- 템플릿 시트(데이터 탭, 변수정의 탭) 생성
- 메뉴 구성
- 변수정의 파싱(척도, 값 레이블, 결측코드)
- 목록별 결측 제거(listwise deletion, SPSS 기본값)

### 1단계 확률분포
- 정규, t, F, χ² 누적확률과 역함수
- 모든 p값 계산의 토대가 된다.

### 2단계 기초
- 빈도분석, 기술통계
- 정규성 검정(Jarque-Bera)
- 등분산 검정

### 3단계 평균 비교
- 단일표본, 독립표본, 대응표본 t검정
- 일원 ANOVA
- 사후검정(Tukey, Games-Howell 등)

### 4단계 관계
- 피어슨, 스피어만 상관
- 교차분석(카이제곱)

### 5단계 회귀
- OLS(다중회귀, 더미 변수, 표준화 계수, 공선성 진단)

### 6단계 화면 완성
- 결과표 서식
- 결과를 시트로 내보내기
- 오류 안내

### 7단계 확장
순서와 이유 (2026-10-21):
1. **Shapiro-Wilk** — 비모수 추천의 판단 근거. 작은 표본에서 JB보다 믿을 만하다.
2. **비모수 검정** — 정규성이 깨졌을 때의 대안이라 t검정·ANOVA 바로 뒤에 필요하고, 구현이 가볍다(순위와 정규·χ² 근사).
3. **신뢰도(크론바흐 α)** — 설문 분석에서 거의 항상 쓰고, 계산이 단순하다.
4. **조절효과** (2026-10-22 추가) — 이미 있는 OLS 회귀 위에 상호작용항을 얹는 것이라 가볍고, 사회과학 논문에서 자주 쓴다.
5. **매개효과** (2026-10-22 추가) — 회귀 두 번과 간접효과 신뢰구간(부트스트랩)이면 되어 조절효과 다음이 자연스럽다. 조절효과·매개효과 둘 다 회귀 계수와 공분산 행렬이 필요하므로 `Stats_Regression.js`의 QR 계산을 재사용한다.
6. **로지스틱 회귀** — 반복 계산(IRLS)과 수렴 처리가 필요해 무겁다.
7. **요인분석(EFA)** — 고유값 분해, 회전 등 무겁고, 필요 여부가 불확실하다. CFA·SEM은 별도 검토 대상(8-6).

**조절효과 설계안 (7d) — 사용자 결정(2026-10-22): 조절변수는 연속형+범주형, 상호작용 그림 포함. 구현 완료(0.17.0)**
- 모형(Hayes PROCESS 모델 1에 해당): Y = b0 + b1·X + b2·W + b3·X·W (+ 공변량). 핵심은 b3(상호작용)의 유의성과 ΔR² (상호작용항을 넣을 때의 R² 증가, F 변화량).
- 옵션: **평균 중심화**(기본 켬, X·W를 각각 평균 중심화해 곱하면 공선성이 줄고 b1·b2가 평균에서의 효과가 됨), 조절변수가 **범주형**이면 더미로 변환(기준 범주 선택은 회귀와 같은 방식).
- 결과: 모형 요약, 계수표(B, SE, t, p, 신뢰구간), 상호작용 ΔR², **단순기울기**(조절변수가 평균 −1SD, 평균, +1SD일 때 X의 효과와 t, p; 범주형이면 범주별), **Johnson-Neyman** 구간(조절변수의 어느 값부터 X의 효과가 유의해지는지), 상호작용 그림(조절변수 수준별 회귀선, 기존 `Charts.js`에 선 그래프 추가).
- 구현: 상호작용항은 분석 안에서 만들고(시트에 열을 쓰지 않음) 필요하면 변수 계산에 `평균 중심화`·`곱 변수`를 추가한다. 단순기울기의 표준오차는 계수 공분산 행렬로 계산한다 (se² = Var(b1) + 2w·Cov(b1,b3) + w²·Var(b3)).
- 기준값: numpy로 독립 구현한 OLS와 대조(계수, SE, ΔR², 단순기울기), J-N 경계는 이차방정식 해를 정확 산술로 확인.
- 예제 데이터에 조절변수 후보(예: 직무자율성)를 **맨 뒤 열로 추가**한다 (앞 20개 열의 값은 바꾸지 않는다).

**다변량 거리 측도 설계안 (7h, 2026-10-22 추가) — 사용자 결정(2026-10-23): 근접도 행렬은 화면에 50×50까지 + 새 시트 탭에 저장(최대 500사례), 성향점수 매칭은 최근접 + 마할라노비스 매칭 (둘 다 권장안)**
- 목적: 사례(행) 사이 또는 변수(열) 사이가 얼마나 다른지(또는 비슷한지)를 숫자로 보여 주고, 마할라노비스 거리로 **다변량 이상치**를 찾는다. 군집분석·다차원척도법의 기초가 되는 근접도(proximity) 행렬이다.
- 입력: 숫자 변수 2개 이상. "사례 간 거리"(기본)와 "변수 간 거리" 중 선택. 결측은 목록별 제거(선택한 변수가 모두 유효한 사례만).
- 측도 (구간·연속 자료): 유클리드 거리, 제곱 유클리드 거리, 맨해튼(블록, 시티블록) 거리, 체비쇼프(최대 차이) 거리, 민코프스키 거리(차수 p 입력), 코사인 유사도·거리, 피어슨 상관 거리(1 − r), **마할라노비스 거리**. 이분(0/1) 자료는 별도 선택: 단순일치, Jaccard, Dice, Hamming. 거리(비유사성)와 유사성을 구분해 표기한다.
- 표준화 옵션: 없음(기본), z점수, 범위 0~1, 범위 −1~1, 최댓값 1, 평균 1, 표준편차 1 (변수별, 변수 간 거리면 사례별). 변수의 단위가 다를 때(예: 연령과 소득) 표준화하지 않으면 큰 단위가 거리를 지배한다는 경고를 보여 준다.
- 결과: ① 사례 처리 요약, ② 근접도 행렬(사례 수가 많으면 앞 N×N만 표시하고 요약 통계 — 최소·평균·최대, 가장 가까운/먼 쌍 — 로 대체, 전체 행렬은 시트 내보내기 옵션으로), ③ 마할라노비스 선택 시 사례별 D², 자유도(변수 수) k의 χ² 근사 유의확률, p < .001인 사례 목록(이상치 후보)과 임계값, ④ 선택 시 D²를 `데이터` 탭의 새 열로 저장(변수 계산의 새 열 쓰기 기능 `Compute.js`를 재사용, 이름 중복 거부·미리보기 포함).
- 한계와 비용: 사례 간 거리 행렬은 n² 개라 표시는 최대 N(예: 200)까지, 마할라노비스는 O(n·k²)라 `MAX_ROWS`(50,000건)까지 가능. 마할라노비스는 공분산 행렬의 역행렬(촐레스키, `choleskySolve_` 재사용)이 필요하고 변수 사이 공선성이 완전하면 계산할 수 없다는 안내를 한다.
- 확인할 것(착수 전): 마할라노비스의 공분산 분모(표본 n−1을 쓴다고 보고 SPSS 저장 값과 대조), 이상치 기준(p < .001 관행), 유사성/거리 용어, 저장 열 이름 규칙(예: `마할라노비스_D2`).
- 기준값: `scipy.spatial.distance`(pdist, cdist: euclidean, sqeuclidean, cityblock, chebyshev, minkowski, cosine, correlation, mahalanobis, jaccard, dice, hamming 등)와 scipy `chi2`로 대조한다 (scipy의 mahalanobis는 공분산 역행렬을 직접 받으므로 numpy 표본 공분산의 역행렬을 넘겨 독립 계산).
- 예제 데이터: 기존 연속 변수(연령, 근무연수, 월소득, 성과점수 등)에 마할라노비스 이상치 사례가 있는지 먼저 본다. 없으면 이상치 연습용 열(예: 두 변수가 각각은 정상 범위인데 조합이 이상한 사례)을 **맨 뒤 열로 추가**한다 (앞 26개 열의 값은 바꾸지 않는다).
- 후속 후보(별도 계획, 이 거리를 재사용): 군집분석(계층적 군집, K-평균), 다차원척도법(MDS). 8번에 "나중에 검토할 일"로 올려 둔다.

**성향점수 매칭 설계안 (7h의 둘째 부분, 2026-10-22 추가, 7f 로지스틱 회귀 뒤, 착수 전에 사용자와 확정)**
- 목적: 처치(0/1)를 받은 집단과 받지 않은 집단이 공변량에서 비슷해지도록 사례를 짝지어 처치 효과(ATT)를 추정한다 (관찰 연구의 선택 편향 보정). 7h의 마할라노비스 거리와 7f의 로지스틱 회귀를 재료로 쓴다.
- 입력: 처치 변수(0/1, 명목 2범주), 공변량(숫자·범주, 범주는 더미), 결과변수(숫자, 선택). 결측은 목록별 제거.
- 성향점수: 처치 ~ 공변량 로지스틱 회귀의 예측확률(logit 척도로 매칭).
- 매칭: **최근접 이웃**(1:1 또는 1:k, 복원/비복원), **캘리퍼**(logit 성향점수 표준편차의 0.2배가 관행, 값 입력), 동점은 시드로 무작위, 마할라노비스 매칭(캘리퍼 안에서 공변량 마할라노비스 거리가 가장 가까운 이웃) 선택. 매칭에 실패한 처치 사례 수를 알린다.
- 결과: 성향점수 모형 요약, **공통 지지 영역**(두 집단의 성향점수 범위와 겹치는 구간), 매칭 요약(처치 N, 짝지은 N, 버린 N), **균형 진단**: 공변량별 표준화 평균 차이(SMD)와 분산비의 매칭 전·후 비교(|SMD| < 0.1이 관행, 표와 그림), 매칭 표본에서의 효과 추정(결과변수가 있으면 평균 차이와 신뢰구간, 짝 t검정 또는 가중), 성향점수 분포 그림.
- 저장: 매칭 ID(짝 번호)와 가중치를 `데이터` 탭의 새 열로 저장(변수 계산의 새 열 쓰기 재사용, 미리보기와 이름 중복 거부 포함).
- 한계: 미관측 교란은 보정하지 못한다는 안내, 처치 집단이 매우 작거나 공통 지지가 거의 없으면 경고. 효과 추정의 표준오차는 매칭을 무시한 단순 검정이 낙관적일 수 있어 짝지은 자료로 계산하고 부트스트랩은 후속.
- 기준값: numpy로 독립 구현한 로지스틱 IRLS와 전수 탐색 매칭(작은 자료에서 모든 후보를 비교)으로 대조한다 (scikit-learn, statsmodels는 설치돼 있지 않다).
- 예제 데이터: 처치 변수 후보로 `집단`(A, B, C 중 둘)이나 새 이분 변수가 필요한지 먼저 본다 (앞 26개 열은 그대로, 새 열은 맨 뒤에 별도 난수열로 추가).

**k-평균 군집분석 설계안 (7i, 2026-10-22 추가, 착수 전에 사용자와 확정)**
- 입력: 숫자 변수 2개 이상, 군집 수 k(2~10), 표준화 옵션(z점수 권장, 단위가 다르면 안내), 시드, 시작 횟수(기본 10), 최대 반복(기본 100). 결측은 목록별 제거.
- 알고리즘: **k-means++ 시작점**(시드로 재현) + Lloyd 반복, 시작을 여러 번 해서 군집 내 제곱합이 가장 작은 결과를 쓴다. 빈 군집이 생기면 가장 먼 사례로 다시 채운다. 수렴 반복 수와 수렴 여부를 알린다.
- 결과: 사례 처리 요약, **최종 군집 중심표**(변수별 평균, 표준화했으면 원래 단위로도), 군집별 사례 수와 비율, 군집 내 제곱합과 총 제곱합 대비 설명 비율, 군집 간 거리, 변수별 군집 간 F(기술적 참고, 군집이 데이터에서 만들어졌으므로 유의확률은 해석하지 않는다는 주석), 사례별 군집 번호와 군집 중심까지의 거리.
- 군집 수 판단 보조: k = 2~10의 군집 내 제곱합 곡선(엘보 그림)과 평균 실루엣(선택, 사례 많으면 표본), 군집 크기가 매우 불균형하면 경고.
- 저장: 군집 번호(와 거리)를 `데이터` 탭의 새 열로 저장 (변수 계산의 새 열 쓰기 재사용).
- 한계: 연속 변수와 구형 군집, 이상치와 시작점에 민감, k는 사용자가 정한다. 대용량은 반복 비용이 크므로 사례 수와 반복에 상한을 둔다 (사례 `MAX_ROWS` 50,000건까지, 시간 예산 안에서 시작 횟수를 줄이는 안내).
- 기준값: `scipy.cluster.vq.kmeans2`(minit='matrix'로 같은 초기 중심)와 같은 초기 중심에서 같은 최종 중심·할당·군집 내 제곱합이 나오는지 대조하고, k-means++와 시작 횟수 경로는 목적 함수(군집 내 제곱합)가 독립 구현보다 나쁘지 않은지와 같은 시드의 재현성으로 확인한다. SPSS의 빠른 군집(QUICK CLUSTER)은 초기 중심 선택이 달라 결과가 다를 수 있다는 점을 안내한다.
- 예제 데이터: 연속 변수(연령, 근무연수, 월소득, 성과점수 등)로 군집이 보이는지 먼저 확인하고, 약하면 군집 연습용 열을 맨 뒤에 추가한다.

**의사결정나무(CART) 설계안 (7j, 2026-10-22 추가, 착수 전에 사용자와 확정)**
- 입력: 종속변수 1개(**명목·서열 → 분류 나무(지니 불순도)**, **연속 → 회귀 나무(제곱오차 감소)**), 예측변수 여러 개(숫자, 서열, 명목). 결측은 목록별 제거(대리 분할은 하지 않는다).
- 알고리즘: 이진 분할만 하는 CART. 연속·서열 변수는 정렬해 인접 값의 중간 임계값을 모두 시험하고, 명목 변수는 범주를 반응 비율(회귀는 평균) 순으로 정렬해 부분집합 분할을 선형 탐색한다(이진 분류와 회귀에서 최적). 중지 조건: 최대 깊이, 노드 최소 사례 수, 부모·자식 최소 크기, 최소 불순도 감소. **비용복잡도 가지치기**(α 후보를 만들고 교차검증으로 고르거나 1SE 규칙), 교차검증은 시드로 재현.
- 결과: 나무 구조 표(노드 번호, 분할 규칙, N, 불순도, 분류 비율 또는 평균), **나무 그림**(SVG, 노드에 N과 예측), 변수 중요도(불순도 감소 합), 분류는 혼동 행렬과 정확도·민감도·특이도(이분일 때) 표, 회귀는 R²·RMSE, 교차검증 성능과 가지치기 곡선(복잡도 대 오차).
- 저장: 예측값과 소속 노드 번호를 `데이터` 탭의 새 열로 저장 (변수 계산의 새 열 쓰기 재사용).
- 한계: 불안정성(자료가 조금 바뀌면 나무가 크게 달라짐)과 과적합을 안내하고, 범주가 많은 명목 변수(10개 이상)는 분할 탐색을 제한한다. SPSS의 CHAID, QUEST는 하지 않는다. 사례는 `MAX_ROWS` 이내, 깊이에 상한을 둔다.
- 기준값: scikit-learn이 설치돼 있지 않아(필요하면 사용자 승인 후 `py -3.12 -m pip install scikit-learn`) 우선 numpy 전수 탐색으로 독립 구현해 모든 분할 후보를 비교한 값과 대조한다. 동점 분할의 선택 순서, 임계값(중간값 vs 관측값)은 프로그램마다 달라 비교 조건을 맞춘다.
- 예제 데이터: 분류용으로 `합격`(0/1)과 `학력`, 회귀용으로 `성과점수`를 쓸 수 있다 (새 열은 필요 없는지 먼저 확인).

**매개효과 설계안 (7e) — 사용자 결정(2026-10-22): 매개변수 여러 개(병렬), 부트스트랩 + Sobel. 구현 완료(0.18.0). 부트스트랩 횟수는 사례 수 × 횟수 ≤ 2.5e7이 되도록 줄이되 1,000회 아래로는 내리지 않는다.**
- 모형(PROCESS 모델 4): M = a0 + a·X (+ 공변량), Y = c0' + c'·X + b·M (+ 공변량). 총효과 c = c' + a·b, **간접효과 = a·b**.
- 간접효과의 유의성: ① **부트스트랩 퍼센타일 신뢰구간**(기본 5,000회, 시드 입력으로 재현 가능, 표본을 다시 뽑아 a·b를 반복 계산 — 세 변수 회귀는 닫힌 식이라 Apps Script 6분 제한 안에서 충분히 빠름) ② Sobel 검정(참고) ③ 몬테카를로 신뢰구간(선택). 신뢰구간이 0을 포함하지 않으면 유의.
- 결과: a, b, c, c' 경로 표(계수, SE, t, p, 신뢰구간), 총효과·직접효과·간접효과 표, 간접효과/총효과 비율, 매개의 종류(완전·부분)를 단정하지 않고 간접효과와 직접효과의 유의성만 보여 준다. 경로도(그림)는 HTML/SVG로 간단히.
- 확장(이번 범위 밖, 요청이 있을 때): 다중 매개(병렬 PROCESS 4, 직렬 6), 조절된 매개(7, 8, 14), 범주형 X.
- 기준값: 같은 난수(LCG)와 같은 추출 방식을 쓰는 python 독립 구현으로 부트스트랩 결과까지 정확히 대조, 경로 계수는 numpy OLS와 대조.
- 예제 데이터에 매개변수 후보(예: 직무몰입)를 맨 뒤 열로 추가 (근무연수 → 직무몰입 → 성과점수 구조, 일부는 완전 매개 아님).

**비모수 추천 메시지 설계 (사용자 결정: 분석 결과에 자동 점검)**
- t검정(독립·대응·일표본), 일원 ANOVA, 상관분석(피어슨)이 결과 안에서 정규성(집단별, 대응표본은 차이값)과 등분산(집단 비교)을 자동 점검하고, 가정이 의심되면 결과 아래 경고로 해당 비모수 검정을 추천한다 (독립 t → Mann-Whitney U, 대응·일표본 t → Wilcoxon, ANOVA → Kruskal-Wallis, 피어슨 → 스피어만).
- 옵션 `가정 점검`(기본 켬)으로 끌 수 있다. 정규성·등분산 검정 결과에도 판정 문구를 붙인다.
- 표본이 크면(대략 n ≥ 100) 정규성 검정이 사소한 이탈에도 기각되므로, 이때는 기각만으로 비모수를 권하지 않고 왜도·첨도와 함께 보라는 문구로 바꾼다.
- 추천은 판단을 돕는 안내일 뿐이며 분석을 막거나 바꾸지 않는다.

### 3단계 설계 결정 (2026-10-21, SPSS와 같은 방식을 기본값으로 정함)
3단계는 두 번에 나눠 진행한다. **3a: t검정 3종**, **3b: 일원 ANOVA와 사후검정** (Tukey·Games-Howell에 필요한 Studentized range 분포를 `Distributions.js`에 추가해야 해서 따로 분리).

| 분석 | 역할 칸 | 옵션 |
| --- | --- | --- |
| 일표본 t검정 | 변수(여러 개) | 검정값(기본 0), 신뢰수준(기본 95) |
| 독립표본 t검정 | 종속변수(여러 개), 집단변수(1개, 집단이 정확히 2개) | 신뢰수준 |
| 대응표본 t검정 | 변수1(1개), 변수2(1개) | 신뢰수준 |

- 결과표는 SPSS 구성을 따른다: 기술통계 표 + 검정 표. 독립표본은 Levene 검정(평균 기준)과 "등분산을 가정함 / 가정하지 않음(Welch)" 두 행을 한 표에 둔다. 대응표본은 쌍 통계량, 상관, 검정 3표
- 평균차이는 SPSS와 같이 **집단1 − 집단2**(집단은 값이 작은 순), **변수1 − 변수2**
- 유의확률은 단측(양측의 절반, SPSS와 같음)과 양측을 모두 보여준다
- 독립표본의 집단변수는 집단이 정확히 2개여야 한다. SPSS의 "집단 정의"(3개 이상 중 두 값 선택)는 지금은 넣지 않는다
- 대응표본은 한 번에 한 쌍만 분석한다 (여러 쌍은 반복 실행)
- 결측은 검정에 필요한 변수가 모두 유효한 사례만 쓴다 (독립: 종속·집단, 대응: 두 변수)
- 소수점은 통계량 3자리, p값은 `.043`/`<.001` 형식으로 고정한다 (사용자 설정은 보류)
- 집단 값은 값 레이블만 표시한다 (빈도분석과 동일, 병기 옵션은 보류)
- 효과크기(Cohen's d)는 이번에는 넣지 않는다 (나중에 검토)

### 4단계 설계 결정 (2026-10-21, SPSS와 같은 방식을 기본값으로 정함)
4단계도 두 번에 나눈다. **4a: 상관분석**, **4b: 교차분석**.

| 분석 | 역할 칸 | 옵션 |
| --- | --- | --- |
| 상관분석 | 변수(2개 이상) | 피어슨(기본 켜짐), 스피어만, 목록별 결측 제거, 신뢰구간(Fisher z), 신뢰수준 |
| 교차분석 | 행 변수(1개), 열 변수(1개) | 기대빈도, 행 %(기본 켜짐), 열 %, 전체 %, 조정된 표준화 잔차, 효과크기(기본 켜짐) |

- **상관분석 표**는 SPSS의 행렬 형식이다: 변수마다 상관계수 / 유의확률(양측) / N 세 줄, 열은 변수. 결측은 **쌍별(pairwise)이 기본**이고 옵션으로 목록별. 스피어만은 순위(동순위는 평균순위)의 피어슨 상관이고 유의확률은 t 근사(자유도 N−2, SPSS·scipy와 같음)
- 피어슨의 신뢰구간은 Fisher z 변환으로 구한다 (n > 3). 켜면 변수 쌍별 표가 따로 나온다. 켄달의 타우는 넣지 않는다
- **교차분석 검정 표**: Pearson 카이제곱, 우도비, (2×2) 연속성 수정과 Fisher 정확검정(양측·단측), (두 변수가 모두 숫자 코드일 때) 선형 대 선형 연관, 유효 케이스 수. 기대빈도 5 미만 셀의 비율과 최소 기대빈도를 각주로 알린다
- **효과크기**: 파이(2×2만, 부호 있음), Cramér의 V, 분할계수
- 범주 수는 변수당 최대 30개, 한 번에 변수 한 쌍만 분석한다 (여러 쌍은 반복 실행)
- 표 안에서 행마다 숫자 형식이 달라서(빈도는 정수, 퍼센트는 소수 1자리, p값은 `<.001` 형식) 결과 객체의 행에 `_fmt`(행 단위 서식)를 지원한다

### 5단계 설계 결정 (2026-10-21, SPSS와 같은 방식을 기본값으로 정함)
5단계는 OLS 다중회귀 한 가지다.

| 역할 칸 | 내용 |
| --- | --- |
| 종속변수 (1개) | 숫자 변수 |
| 독립변수(공변량, 여러 개, 선택) | 숫자 변수. 그대로 넣는다 |
| 범주형 독립변수 (여러 개, 선택) | 명목·서열 변수. **더미 변수로 자동 변환** (SPSS는 사용자가 직접 만든다) |

공변량과 범주형 중 적어도 하나는 있어야 한다.

- **입력(Enter) 방식 한 가지**만 한다. 단계적(stepwise) 선택은 하지 않는다
- **더미 변수**: 기준 범주는 값이 가장 작은 범주(첫 범주)가 기본이고, 옵션 "기준 범주를 마지막 범주로"로 바꾼다. 계수 이름은 `변수 = 범주`로 표시하고 기준 범주는 각주에 적는다. 범주는 변수당 10개까지
- **결과표 (SPSS 구성)**: 모형 요약(R, R², 수정 R², 추정값의 표준오차), 분산분석(회귀·잔차·합계), 계수(B, 표준오차, 표준화 계수 베타, t, 유의확률, 공차, VIF). 옵션: B의 신뢰구간, 공선성 진단(고유값·조건지수·분산 비율, SPSS와 같은 방식), 더빈-왓슨
- **결측**: 목록별 제거 (모든 변수가 유효한 사례만)
- **수치 방식**: 변수를 평균으로 중심화한 뒤 Householder QR로 푼다 (정규방정식을 직접 풀지 않는다). 상수항과 그 표준오차는 중심화한 결과에서 복원한다. 완전 공선성(어떤 변수가 앞선 변수들의 선형결합)이거나 값이 모두 같은 변수는 변수 이름을 알려 주는 오류로 처리하고, VIF가 10을 넘으면 경고한다
- 잔차 분석 그림, 영향력 진단(Cook 거리 등), 위계적 회귀(블록), 로지스틱 회귀는 이번 범위가 아니다

### 6단계 설계 결정 (2026-10-21)
6단계는 세 덩어리로 나눈다. **6a: 차트**, **6b: 시트로 내보내기**, **6c: 옵션 기억과 오류 안내**.

- **내보내기**: 결과를 **시트의 `결과` 탭**에 표 서식 그대로 쓴다 (결과별 버튼과 전체 내보내기). 숫자는 숫자로 쓰고(정수·소수 서식 적용), p값은 HTML과 같은 문자열(`<.001`, `.043`)로 쓴다. 차트는 **그림(PNG)으로 넣는다**: 서버(Apps Script)는 SVG를 이미지로 바꿀 수 없으므로 분석 창이 브라우저의 canvas로 SVG를 PNG로 바꿔 서버로 보내고, 서버가 그림 높이만큼 행을 비워 두고 `insertImage`로 삽입한다 (처음에는 "내보내지 않는다"로 정했으나 이 방법으로 바꿈, 2026-10-21)
- **차트 (기본 4종, 외부 라이브러리 없이 SVG 직접 작성)**: 빈도분석의 막대그래프, 기술통계의 히스토그램(정규곡선 포함), 상관분석의 산점도(쌍별, 회귀선), 독립표본 t검정·ANOVA의 상자그림(튜키의 힌지로 사분위수를 계산하고 1.5·3 × 힌지 간격 밖을 이상치·극단값으로 표시. SPSS가 같은 방식을 쓰는 것으로 알려져 있으나 직접 대조는 못 함). 모두 분석 창의 체크 옵션이며 기본은 꺼 둔다
- **소수점**: 고정 (통계량 3자리, 퍼센트 1자리, p값 `.043` 형식). 사용자 설정은 만들지 않는다
- **설정 기억**: 분석별 **옵션만** 사용자 속성(`UserProperties`)에 저장해 창을 다시 열어도 유지한다. 변수 선택은 데이터가 바뀔 수 있어 저장하지 않는다
- **오류 안내**: 입력 오류(사용자가 고칠 수 있는 것)는 지금처럼 그대로 보여주고, 프로그램 오류(TypeError 등)는 "예기치 않은 오류" 안내로 바꿔 보여주면서 실행 로그에 원인을 남긴다. 사례 수가 많을 때(2만 건 초과) 느릴 수 있다는 경고를 준다

### 템플릿 배포 방식의 영향
- 사용자는 "사본 만들기"로 시트를 복사하고, 컨테이너 바인딩 스크립트도 함께 복사된다. 외부 서비스나 배포 절차가 필요 없다
- 사본마다 첫 실행 때 권한 승인이 필요하고 "확인되지 않은 앱" 경고가 뜬다. 사용 안내(README)에 승인 방법을 적는다
- 이미 복사된 사본에는 코드 수정이 자동 반영되지 않는다. 메뉴에 버전 표시(`Stat4SW 통계분석 > 정보`)를 두고, 업데이트는 "새 템플릿을 다시 복사해 데이터만 옮기는" 방식으로 안내한다
- 개발 중인 이 시트를 그대로 배포하면 작업 중 코드가 섞이므로, 배포용 템플릿은 릴리스 시점에 따로 복사해 만든다
- 템플릿에는 `데이터`·`변수정의` 탭을 비워 두고 포함한다. 예제 데이터는 메뉴(`예제 데이터 채우기`)로만 넣는다

### 화면 구조 결정
- 메뉴 "Stat4SW 통계분석 > 분석 창 열기"로 큰 모달리스 대화상자(SPA) 하나를 연다. 왼쪽은 변수 목록·옵션, 오른쪽은 결과 누적 영역
- 모달리스라 분석 중에도 시트 편집 가능
- 분석 함수는 순수 함수로 작성하고 `module.exports` 가드를 두어 Node에서 직접 테스트한다

### 2단계 설계 결정 (2026-10-21)
- **결과 누적**: 계속 누적한다. 개별 삭제와 전체 지우기를 제공한다 (창을 닫으면 사라진다)
- **변수 선택**: 변수 목록에서 선택해 분석별 "역할 칸"(예: 변수, 종속변수, 요인)으로 보낸다. ▶ 버튼 또는 더블클릭. 분석마다 칸 정의와 허용 척도가 다르다
- **차트**: 이번 단계는 표만 만든다. 차트(SVG 직접 작성)는 6단계에서 한꺼번에 처리한다
- **렌더링 위치**: 결과 객체 → HTML 변환은 서버(`Render.js`)에서 한다. 순수 함수라 Node에서 테스트할 수 있고, 나중에 시트 내보내기에서도 같은 결과 객체를 쓴다
- 결과 객체 형식은 [설계-결과객체.md](설계-결과객체.md) 참고

지금 진행하지 않고 목록으로만 둔다. 착수할 때 이 항목의 확인 사항부터 정리한다. (2026-10-21 추가)

### 8-1. AI 결과 해석 보조 (2026-10-23 사용자 방침으로 전면 개정, 구현 전 설계 문서; **2026-10-27 보류: AI 없는 버전은 UI 점검으로 마무리하고, AI 버전은 새 파일(새 프로젝트)에서 시작한다. 이 문서의 설계 내용만 보존한다**)

**목적 (확정)**: 분석 **결과를 이해하고 보고서에 옮기기 쉽게 정리**하도록 돕는다. 이전 계획의 "AI로 같은 데이터를 다시 분석해 교차 검증"은 **하지 않는다** (언어 모델은 계산기로 믿기 어렵고, 원자료를 보내야 하기 때문). AI는 이 도구가 계산한 결과를 **해석·서술**만 한다. 숫자를 새로 계산하거나 바꾸지 않는다.

**진행 방식 (사용자 결정, 2026-10-23)**: 통계기능이 끝난 **최종본(AI 없음)을 먼저 확정**하고, 그 뒤에 **사본을 만들어 AI를 이어서 구현**한다. 그러면 최종본은 외부 호출과 외부 요청 권한이 없는 "기본판" 그대로이고, AI 사본이 "확장판"이 되어 두 코드를 동시에 유지하는 이중 작업을 지금 하지 않는다. 구체 방법(제안): 최종본 커밋에 로컬 git 태그를 달고, 같은 저장소에서 로컬 분기(`ai`)와 별도 Apps Script 프로젝트(`.clasp.json`)로 사본을 둔다 (원격 없이 로컬만). AI 코드는 새 파일(`Ai*.js`, 패널)과 최소한의 연결점만 추가하는 방식으로 만들어, 나중에 최종본의 오류 수정을 분기에 합치는 일(`git merge`)이 쉽게 한다. 최종본에서 고친 것은 분기에 합쳐 주는 책임이 따른다. 사본 안에서도 키 없이 쓰는 프롬프트 복사 기능이 기본이고, 키를 넣으면 화면 안에서 답을 보여 준다.

**원칙**
1. **원자료(raw data)는 절대 나가지 않는다.** 사례별 값, 사례 번호·행 번호, 개인을 식별할 수 있는 값은 프롬프트에도 API 호출에도 포함하지 않는다. 나가는 것은 **이 도구가 계산한 결과의 요약**(표의 제목, 열 머리글, 표시된 숫자, 각주, 경고)뿐이다.
2. **키 없이도 쓸 수 있다 (기본 기능).** 키를 입력하지 않으면 도구가 **프롬프트(AI에게 시킬 문장)를 만들어 주고 복사 버튼**을 제공한다. 사용자는 원하는 AI(Gemini, ChatGPT, Claude 웹 등)에 직접 붙여 넣어 묻는다. 이 경로는 외부 호출이 전혀 없다.
3. **키를 입력하면 확장 기능**: 같은 프롬프트를 도구가 AI에 대신 보내고 **답을 분석 창 안에 보여 준다** (복사, 필요하면 `결과` 탭에 쓰기). 키 입력은 사용자가 원할 때만 한다.
4. **보내기 전에 항상 무엇이 나가는지 보여 준다** (미리보기). 사용자가 확인하고 고치고 나서만 복사하거나 전송한다. 자동 전송은 없다.

**사용자가 보는 화면 (안)**
- 결과 카드의 `시트로 내보내기` 옆에 **`AI로 보고서용 정리`** 버튼. 누르면 패널이 열린다:
  1. 포함할 표 선택(체크박스, 기본은 핵심 표) — 사례 단위 표(아래 "보내지 않는 것")는 목록에 나오지 않는다
  2. 정리 방식 선택: **쉬운 말 요약** / **보고서 문장(결과 서술)** / **주의할 점(가정, 한계)**, 말투(논문체, 보고서체, 쉬운 말)
  3. **미리보기**(편집 가능한 텍스트): AI에게 줄 지시문과 결과 요약이 그대로 보인다. 변수 이름 가리기 옵션(변수A, 변수B로 바꿈, 기본값은 구현 때 정함)
  4. **프롬프트 복사** (키 없이도 항상 있음) / **AI에게 보내기** (키가 있을 때만 활성)
  5. 답이 오면 패널에 표시, **복사**, (선택) **결과 탭에 쓰기**. "AI가 쓴 문장이므로 숫자와 해석을 직접 확인하세요" 문구를 항상 붙인다.
- 키 설정: 분석 창의 설정(또는 메뉴)에서 입력/삭제. 저장된 키는 **다시 화면에 보여 주지 않고** "저장됨(끝 4자리)"만 표시한다.

**무엇이 나가고 무엇은 나가지 않는가**
- 나감(허용 목록 방식): 분석 이름, 표 제목, 열 머리글, 행 이름(변수 이름, 값 레이블), 표시된 숫자(결과 객체의 서식을 거친 문자열), 표 각주, 경고 문구, 옵션 요약(예: "신뢰수준 95%").
- **보내지 않음**: 원자료, 사례 단위 표(거리·유사도의 행렬과 이상치 후보 표처럼 행 번호가 이름인 표, 매칭 ID·군집 번호 같은 저장 열, 성향점수 사례 목록), 차트(산점도의 점은 원자료와 같다. 상자그림·히스토그램도 1차 버전에서는 제외하고 표의 요약값으로 대신함), 변수 목록 전체, 시트 이름·파일 이름. 알 수 없는 새 블록은 기본적으로 제외(허용 목록에 있는 것만 포함).
- 크기 한도: 한 번에 약 6,000자, 표당 최대 30행. 넘으면 앞부분만 넣고 "일부만 보냄"을 미리보기에 표시한다. 빈도표처럼 값이 많아 개별 값이 드러날 수 있는 표는 20범주 초과면 제외한다.
- 이 규칙은 구현에서 **순수 함수 `buildAiInput_(result, selection, options)`** 로 한 곳에서 만들고, 테스트가 (1) 사례 단위 표와 차트가 절대 포함되지 않는지 (2) 시험 데이터의 원자료 값이 출력에 없는지 (3) 한도와 가리기 옵션이 동작하는지 확인한다.

**프롬프트 설계 (초안)**
- 역할: "사회복지·사회과학 연구 보고서 작성을 돕는 통계 해설자". 지시: 아래 표의 **숫자만 사용하고 새로 계산하지 말 것**, 모르는 값은 "자료에 없음"이라고 쓸 것, 인과를 단정하지 말 것(관찰 연구면 연관으로 서술), 효과크기와 신뢰구간이 있으면 함께 해석, 가정 점검 경고가 있으면 한계로 언급, 한국어로 출력.
- 출력 형식: 선택한 정리 방식별 고정 구조(예: 핵심 한 줄, 결과 서술 2~4문장, 해석 시 주의점). 분석별 보조 문구(예: t검정은 "평균 차이와 효과크기", 회귀는 "R², 유의한 계수", 로지스틱은 "오즈비 해석")는 `Advisor.js`처럼 코드 안 상수로 둔다.
- 개발 중 Stat_Assistant의 `PromptTemplates`(추천기법별 사회복지 성과평가 문장 템플릿)를 참고하되 그대로 가져오지는 않는다 (입력 필드가 원자료 기반이라 맞지 않음).

**API 키 (사용자 결정)**
- 키는 **스크립트 속성(Script Properties)에 저장**하고, 시트를 복사하면 키가 따라오지 않으므로 **사본마다 사용자가 자기 키를 입력**한다. 키 입력 화면과 안내 문구가 필요하다.
- 키는 **서버에서만 사용**한다: 클라이언트(화면)로 돌려주지 않고, 오류 메시지·로그에도 남기지 않는다(마스킹). 키 삭제 버튼을 둔다.
- 주의(문서화): 스크립트 속성은 그 스크립트의 모든 사용자가 공유한다. **시트를 다른 사람에게 편집 권한으로 공유하면 그 사람도 이 키로 호출할 수 있다** (비용·한도 소모). 안내문에 적고, 필요하면 사용자별 저장(`UserProperties`)으로 바꾸는 선택지를 구현 때 다시 묻는다.

**권한과 배포 구조 (중요한 쟁점)**
- API 호출은 `UrlFetchApp`을 쓰며 `https://www.googleapis.com/auth/script.external_request` 권한이 필요하다. 지금 `appsscript.json`에는 `oauthScopes`가 없어 Apps Script가 **코드에 쓰인 서비스를 보고 권한을 자동으로 정한다**. 그러면 `UrlFetchApp`을 쓰는 코드가 하나라도 있으면 **키를 안 쓰는 사용자도** 첫 승인 화면에서 외부 요청 권한을 요구받는다 (8-3 권한 범위 좁히기와 직결).

### 8-2. 정규성 검정에 Shapiro-Wilk 검정 추가 가능 여부 확인 (Shapiro-Wilk는 7a에서 구현함. Lilliefors는 미정)
- 확인할 것: 외부 라이브러리 없이 구현할 수 있는지. Royston(1992, 1995)의 알고리즘(AS R94)은 정규 분위수(`qnorm`, 구현됨)와 다항식 계수표만 있으면 되어 구현은 가능해 보인다. 다만 계수를 정확하게 옮겨야 하므로 `scipy.stats.shapiro` 결과와의 대조 테스트를 먼저 만든다
- 범위: 표본 크기 3~5000. n=3은 정확한 식, 그 이상은 Royston 근사. 범위 밖은 오류 메시지로 안내한다
- 함께 검토: SPSS의 정규성 검정 표는 Kolmogorov-Smirnov(Lilliefors 보정)와 Shapiro-Wilk를 같이 보여준다. SPSS와 같은 결과표가 필요한지에 따라 Lilliefors 검정(p값 근사식 필요)까지 갈지 정한다
- 연결: 지금의 `runNormality`는 Jarque-Bera 한 가지다. 검정 종류를 고르는 옵션으로 확장하거나 결과 표를 검정별로 나눈다 (결과 객체 형식은 바꿀 필요 없음)

### 8-9. 잠재집단분석 (LCA: Latent Class Analysis) — 검토 의견 (2026-10-22, 구현이 어렵다고 보고 검토 항목으로 둠)
- 하는 일: 범주형(이분·서열) 지표 여러 개의 응답 패턴에서 관찰되지 않는 **잠재 집단**을 찾고 집단별 문항 응답 확률(조건부 확률)과 집단 크기를 추정한다.
- 필요한 계산: EM 알고리즘(E 단계 사후 소속확률, M 단계 비율과 조건부 확률 갱신), 로그가능도, 정보 기준(AIC, BIC, 보정 BIC), 엔트로피, 소속 분류 정확도. 시작이 무작위라 **지역 최대**에 빠지기 쉬워 여러 번(수십~수백 번) 시작하고 가장 좋은 가능도를 쓴다. 집단 이름의 순서가 바뀌는 문제(label switching) 정리.
- 어려운 점: ① 모형 선택(집단 수)이 정답이 없고 BIC만으로 부족해 부트스트랩 가능도비 검정(BLRT) 같은 무거운 계산을 쓴다 ② 공변량이 있는 3단계 접근(소속 오분류 보정)과 설명변수의 영향 추정이 복잡 ③ 식별 문제(지표 수에 비해 집단이 많으면 식별 불가), 0/1 경계로 수렴 ④ 검증: poLCA·Mplus 같은 기준 프로그램이 없어 독립 구현끼리만 비교해야 하고 결과가 시작값에 민감해 재현 기준을 세우기 어렵다.
- 구현 가능성 평가(의견): **공변량 없는 기본 LCA**(지표 10개 이하, 범주 5개 이하, 집단 2~5개)는 EM과 정보 기준 정도라 구현할 수 있다. 하지만 해석 지원(집단 수 선택, 불안정한 해 안내)의 부담이 크고 검증 기준이 약해 신뢰를 보증하기 어렵다. 착수 조건: 사용자의 실제 자료와 필요(어떤 지표, 몇 집단)를 확인하고, 기준 프로그램 결과(논문 예제 값)를 확보한 뒤 시작한다. 7i의 k-평균과 7g의 요인분석 뒤로 미룬다.

### 8-10. 다층모형·위계적 선형모형 (HLM: Hierarchical Linear Model) — 검토 의견 (2026-10-22, 구현이 어렵다고 보고 검토 항목으로 둠)
- 하는 일: 학생-학교, 환자-병원처럼 **집단에 묶인 자료**를 한 모형에서 분석한다. 집단 간 변동(급내상관 ICC)을 추정하고, 개인 수준과 집단 수준 변수의 고정효과를 구하며, 절편(필요하면 기울기)이 집단마다 다르게 둔다.
- 필요한 계산: 혼합효과 모형의 **REML/ML 추정**(분산 성분의 가능도를 반복 최적화), 고정효과의 GLS 추정과 표준오차, 분산 성분(집단 수준 분산 τ00, 잔차 분산 σ²), ICC, 모형 비교(−2 로그가능도, AIC, BIC), 자유도 근사(Satterthwaite, Kenward-Roger).
- 어려운 점: ① 확률 기울기(랜덤 기울기)를 넣으면 분산·공분산 행렬이 양정치여야 하는 제약 아래 다차원 최적화가 필요하고 수렴 실패·경계 해(분산 0)가 흔하다 ② 3수준 이상, 교차 분류, 이분형 종속변수(일반화 혼합모형)는 수치 적분이 필요해 범위를 크게 벗어난다 ③ 검정에 쓰는 자유도 근사가 프로그램마다 달라 비교가 어렵다 ④ 검증 기준(R의 lme4, statsmodels MixedLM)이 설치돼 있지 않다(필요하면 사용자 승인 후 설치) ⑤ 설정 화면(수준 변수, 확률 효과 지정)이 복잡.
- 구현 가능성 평가(의견): **2수준 확률절편 모형**(ICC, 고정효과, 분산 성분, REML)은 분산비 한 개를 1차원으로 최적화하는 프로파일 가능도로 비교적 가볍게 구현할 수 있다(영모형 → 개인 수준 예측변수 → 집단 평균 변수). **확률 기울기**는 한 개까지만 시도해 볼 수 있으나 수렴 실패 안내가 필수. 3수준 이상과 비선형 모형은 범위 밖. 착수 조건: 실제 자료의 구조(집단 수, 집단 크기)를 확인하고 statsmodels 설치 허락 또는 독립 구현으로 기준값을 만든다.

### 8-11. 생존분석·콕스 비례위험모형 (Cox Proportional Hazards Model) — 검토 의견 (2026-10-22, 구현이 어렵다고 보고 검토 항목으로 둠)
- 하는 일: 사건(사망, 이탈, 재발 등)이 일어나기까지의 시간 자료를 **중도절단**(관찰이 끝나서 사건을 못 본 사례)을 고려해 분석한다. Kaplan-Meier 생존곡선, 집단 비교(log-rank), Cox 회귀(위험비, HR).
- 필요한 계산: Kaplan-Meier 추정과 Greenwood 분산, log-rank 검정, Cox의 **부분 가능도** 최대화(Newton-Raphson), 동시점 처리(Breslow, Efron), 계수의 표준오차(정보 행렬), 위험비와 신뢰구간, 가능도비·Wald·score 검정, 비례위험 가정 점검(Schoenfeld 잔차 검정).
- 어려운 점: ① 시간가변 공변량, 층화 Cox, 경쟁위험, 군집(frailty) 모형은 범위를 크게 키운다 ② 기준값(R survival, lifelines, statsmodels PHReg)이 설치돼 있지 않아 독립 구현으로 대조해야 한다 ③ 입력 형식(시간 열, 사건 여부 열)과 결과 해석 안내가 새롭다.
- 구현 가능성 평가(의견): **Kaplan-Meier + log-rank + 기본 Cox(고정 공변량, Efron 동시점)는 구현 가능성이 높다**. Cox 계수 추정은 7f 로지스틱 회귀(IRLS, 수렴 처리)와 구조가 같은 반복 계산이라, 로지스틱을 먼저 만든 뒤라면 난이도가 중간이다 (개인 판단: 어렵다고 보셨지만 기본형은 해 볼 만하다). 반면 시간가변 공변량·층화·경쟁위험·비례위험 가정의 정밀 검정은 제외하는 것이 좋다. 착수 조건: 7f 이후, 사용자의 실제 자료 유형을 확인하고 작은 공개 예제(예: 폐암 자료)의 문헌 값이나 독립 구현으로 기준값을 만든다.
