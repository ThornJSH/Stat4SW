### 구현된 기능 (한눈에)
- **기초**: 빈도분석, 기술통계, 정규성(Shapiro-Wilk, Jarque-Bera), 등분산(Levene), 차트 4종(막대·히스토그램·산점도·상자그림)
- **평균 비교**: t검정 3종(+효과크기 Cohen d·Hedges g, 비중심 t 정확 신뢰구간), 일원 ANOVA(+사후검정 4종), **이원 ANOVA**(유형 III·II, 상호작용 그림, 단순 주효과, 사후검정), **반복측정 ANOVA**(Mauchly, GG·HF·하한 교정, Bonferroni 쌍별; **집단변수를 넣으면 집단 × 측정 혼합 설계**: 개체-간 검정, 단순 효과, 상호작용 그림)
- **순위 비교(비모수)**: Mann-Whitney U, Wilcoxon(대응·일표본), Kruskal-Wallis(+Dunn), **Friedman**(+Dunn–Bonferroni), McNemar
- **관계·영향**: 상관(피어슨·스피어만, **통제변수 칸을 채우면 편상관·순위 편상관**), 교차분석, 선형 회귀, **위계적 회귀**(1~4단계, R² 변화 F검정), **서열(비례오즈) 로지스틱**(문턱값·B·Exp(B), Brant 가정 점검), 조절효과, 매개효과, 이분형 로지스틱(H-L, ROC·AUC, 예측값 저장)
- **설문·다변량**: 신뢰도(크론바흐 α), **평가자 일치도**(Cohen·Fleiss kappa, 가중 kappa, 쌍별 kappa), **급내상관 ICC**(6유형), **탐색적 요인분석**(주축분해·주성분, 베리맥스·프로맥스, KMO·Bartlett, 스크리, 병렬분석, 요인 점수 저장), 거리·유사도·마할라노비스, 성향점수 매칭, k-평균, 의사결정나무(CART)
- **생존 분석**: **Kaplan–Meier 생존분석**(중도절단 반영 생존곡선, 시점별 생존율·신뢰구간, 중앙값 등, log-rank·Breslow·Tarone–Ware 집단 비교, 쌍별 비교)
- **연구 설계**: **검정력·표본 크기 계산**(t검정 2종, 일원 분산분석, 상관, 두 비율, 회귀 R²; 데이터 불필요, 효과크기별 표, 검정력 곡선, 탈락 감안 모집 인원)
- **도구**: 분석 창(분석 묶음·한 줄 설명·고급 옵션), 분석 선택 도우미(분석 창 안 + 넓게 보는 메뉴), 변수 설정 편집, 변수 계산, 결과 탭 지우기, 템플릿 시트 만들기, 예제 데이터 채우기, **시험 데이터**(기법별 파이썬 기준값 자료를 시트에 넣고 기대 결과와 비교), 시트로 내보내기

## 5. 설계 결정 (코드만 봐서는 이유를 알 수 없는 것)

- **비모수 추천 기준** (`Stats_Assumptions.js`의 `ADV_*`): 정규성은 3~5,000건은 Shapiro-Wilk, 그 밖은 Jarque-Bera. N ≥ 100에서 기각돼도 |왜도| < 2, |첨도| < 7이면 비모수를 권하지 않고 안내만. N < 10이면 "기각하지 못해도 확인이 어렵다" 안내. 서열 척도 변수는 항상 순위 검정을 권한다. 옵션 `가정 점검`은 클라이언트 기본 켬, 서버는 `options.assumptions`가 참일 때만 동작(옛 테스트 보호).
- **Levene 행 강조**: p ≥ .05 → "등분산을 가정함", p < .05 → "가정하지 않음"(Welch)을 굵게. 일부 통계학자는 처음부터 Welch만 쓰기를 권하는 점을 사용자에게 알렸다.
- **비모수 구현 세부**: Z는 동순위 보정, 연속성 보정 없음(SPSS와 같음). 정확 p는 동순위가 없고 표본이 50 이하일 때만. Wilcoxon의 Z 부호는 양의 순위합 기준(scipy는 부호가 다름 — 크기만 같다).
- **반복측정 ANOVA**: 행 선택은 Mauchly p ≥ .05 → 구형성 가정, 아니면 ε(GG) > .75 → Huynh–Feldt, 그 외 Greenhouse–Geisser를 굵게. **Mauchly 유의확률은 R `mauchly.test`·pingouin의 2차 근사**(2차 항의 `3*k`)를 따른다. 독립 계산(numpy 직접 계산)과 pingouin·statsmodels가 모두 일치했고, SPSS와는 소수 넷째 자리 이하에서 다를 수 있다 (점검 절차서 A-15에 안내). 결측이 있는 사람은 통째로 제외, 측정 횟수 3~12, 사람 수가 측정 횟수보다 적으면 Mauchly는 null.
- **탐색적 요인분석**: 상관행렬(피어슨, 목록별 결측 제거)의 고유분해는 기존 `jacobiEigen_`(Stats_Regression.js)를 쓴다. 주축분해는 초기 공통성 SMC(1 − 1/diag(R⁻¹)), 대각을 공통성으로 바꾼 행렬을 반복 분해해 공통성 변화 1e-6 미만에서 멈춘다(최대 300회; SPSS는 25회·.001에서 멈춰 소수 셋째 자리 차이가 날 수 있음, 점검 절차서 A-61에 안내). 베리맥스는 R `stats::varimax`(Kaiser 정규화, SVD) 알고리즘이고 JS는 극분해를 Jacobi 고유분해로 구하며 수렴을 1e-12로 엄격히 둔다. 요인은 회전 뒤 제곱합 큰 순으로 정렬하고 각 열 합이 양수가 되도록 부호를 맞춘다(`efaCanonical`). 완전히 대칭인 구조(모든 행이 두 선 위에 있는 인위적 자료)에서는 R 알고리즘 자체가 진동해 회전하지 못할 수 있으나 numpy 구현과 같은 결과다. 고유값 1 이상 판정은 1 + 1e-9 초과(직교 변수에서 반올림 오차 방지). 사례 수 ≤ 변수 수는 오류, 변수 50개·요인 수는 주축분해 변수 수 − 1까지. **statsmodels의 `rotate('varimax')`는 Kaiser 정규화를 하지 않아 대조 기준으로 쓰지 못한다**(0.0045 차이). **factor_analyzer의 `FactorAnalyzer.fit`은 설치된 scikit-learn(1.9)과 맞지 않아 쓰지 못하고** `calculate_kmo`, `calculate_bartlett_sphericity`, `Rotator`만 쓴다. 적재 표의 "큰 적재값 굵게"는 행 단위 굵게만 지원돼 구현하지 않았다(대신 작은 값 숨김).
- **일반/고급 모드(1.0.0)**: 분류는 `src/Mode.js`의 `BASIC_ANALYSES_`(18)·`ADVANCED_ANALYSES_`(19)이고 새 분석을 만들면 둘 중 하나에 넣어야 한다(`tests/mode.test.js`가 client.html의 모든 키가 분류됐는지 확인). 서버 `getModeInfo`(데이터와 따로), `getDatasetInfo`·`getAdvisor`가 `advanced`(켜짐 여부, 사용자 속성 `stat4sw.advanced`)와 `advancedKeys`를 돌려주고 분석 창 HTML에는 `modeBootJson_`로 끼워 넣어(**데이터를 못 읽어도 목록이 걸러지게**; 처음에는 `getDatasetInfo` 응답에만 실어 데이터 탭이 없으면 걸러지지 않던 버그가 있었다), 분석 창(`buildAnalysisList`, `isLocked`)과 넓게 보는 도우미(`openBtn`)가 잠긴 분석의 열기 버튼 대신 안내 문구를 보인다. **서버의 `runAnalysis`는 모드를 보지 않는다**(보안이 아니라 화면 단순화). 관리 기능 잠금은 메뉴 래퍼 `menuOpenTestData`(`requireAdvanced_`)로 하고 원래 함수(`openTestData`)는 그대로라 기존 테스트가 유지된다. **새 작업 시작**(`Template.js`의 `startNewWork`, 확인 문구 `NEW_WORK_CONFIRM_` = "지우기", `applyTemplate_`로 실제 작업, `newWorkClearResults_`로 결과 정리)은 모드와 무관하며 예전 `createTemplate`(예/아니오 확인창 단순판)은 기존 테스트와 시트 편집기용으로 남겨 두었다. 개인 사본 안내는 `Menu.js`의 `noticePrivacyOnce_`(사용자 속성 `stat4sw.privacyNoticed`). `getAdvisor`는 Node 단위 테스트에서 `getModeInfo_`가 없으므로 `typeof` 확인 후 꺼짐으로 본다. 정보·저작권 화면은 HTML 템플릿(`<?= APP_VERSION ?>`)이다. **상용 제품 이름 금지 규칙**: `tests/mode.test.js`가 `src/`와 `tests/`의 .js·.html·.py를 검사한다(기준값 JSON과 `tests/ui`는 제외; 문서의 사실 비교는 허용).
- **IPA(0.47.0)**: 이름 접두어 `ip*`(`ipaQuadrant`, `runIpa`), 차트는 `Charts.js`에 `IPA_QUADRANTS_`·`IPA_COLORS_`·`ipaChartBlock`·`renderIpa_`. 그림의 점 이름 배치는 후보 4곳(오른쪽, 왼쪽, 위, 아래)에서 겹침 점수가 가장 낮은 곳을 고르는 단순 방식이고 이름은 14자까지(넘으면 …). 기준선 = 방식 값 + 이동량(직접 지정이면 이동량 무시). 격차 검정은 짝이 모두 있는 사례의 대응표본 t(문항 평균의 차이와는 결측이 있으면 조금 다름). **gas_sim**: 샘플 시트는 변수가 5개라 IPA(변수 6개 필요)는 `REQUESTS` 표에 넣지 못하고 별도 시트를 주입하는 전용 테스트(`GAS 시뮬레이션: IPA ...`)로 확인한다. 요청 키 `importance`, `performance`를 `testdata.test.js`의 요청 키 목록에 추가했다. 선택 도우미 최상위 선택지가 14개가 됐다(`advisor.test.js`의 개수).
- **켄달 타우-b(0.46.0)**: `kendallTauB(x, y, method)`는 `rel*` 접두어가 아닌 공개 이름(피어슨·스피어만과 같은 방식)이고 보조 함수는 `relTieStats_`, `relInversions_`, `relKendallExactP_`. 정확 분포는 순열의 역전 수 분포를 P_k(j) = (1/k)·Σ_{i<k} P_{k−1}(j−i) 누적합으로 O(n·c) 계산하며 자동 규칙(N≤33)에서만 쓰고 큰 N 은 시험하지 않는다(N=3000에서 28초). 한쪽 변수의 동순위 통계는 scipy `_count_rank_tie`와 같은 t, t0, t1. 편상관 경로(`runPartialCorrelation_`)는 `opt.kendall`이면 즉시 오류를 낸다. 요청 키는 기존 `vars`, `controls`이고 옵션 키 `kendall`만 추가.
- **Cochran Q(0.45.0)**: 이름 접두어 `cq*`(`cochranQ(x, pchisq)`가 순수 계산, `runCochran`이 표·그림). Q = (k−1)[kΣC²−T²]/(kT−ΣR²), 분모가 0이면(모든 사람이 모든 측정에서 같은 응답) Q·p·W는 null이고 경고. 0/1 자료의 Friedman 카이제곱과 같아 기준값 생성 때 항등식으로 교차 확인한다. 쌍별은 `Stats_Mcnemar.js`의 `mcnemarExactP`(Node에서는 require, GAS에서는 전역)를 재사용. 성공값 판정 규칙은 이항 검정·Kaplan–Meier와 같다(숫자는 수치, 글자는 문자열). 성공이 한 건도 없으면 오류로 막는다.
- **이항 검정(0.44.0)**: 이름 접두어 `bn*`(`binomTest`, `binomExactCi`, `binomWilsonCi`, `bnCdf`, `bnSf`). 꼬리 확률은 `ibetaPQ_`(P(X≤k)=I_{1−p}(n−k,k+1), P(X≥k)=I_p(k,n−k+1)). 양측은 scipy `binomtest`의 minlike와 같은 정의이고 구현은 최빈값 반대편 경계를 이분 탐색으로 찾는 방식(로그 확률 비교, 상대 허용 1e-7; 최빈값은 ⌈np⌉ 이하, 반대쪽 시작은 ⌊np⌋ 이상임을 이용). 베타 분위수는 `ibetaPQ_` 위의 이분법(Clopper–Pearson). 성공값 일치는 숫자는 수치, 글자는 문자열 비교로 Kaplan–Meier의 사건값과 같은 규칙. 성공값이 변수에 없으면(성공 0건) 오류로 막는다(성공 0건의 검정이 필요한 드문 경우는 지원하지 않음). 요청 키는 `vars`(새 키 없음).
- **Dunnett(0.43.0)**: 이름 접두어 `anova*`(`anovaGL_`, `anovaDunnettProb_`, `anovaSolve_`). 확률 P(모든 |T_i|<q)는 `T_i = (a_i Z_i − b_i Z_0)/u`로 쓰고 Z0는 [−8, 8]을 16구간(통제집단이 작아 a가 0.5 미만이면 32구간)×8절점, u = √(χ²/df)는 분위수(1e-14, 1e-4, 1e-2, 0.1, 0.5, …)로 나눈 8구간×12절점의 밀도 가중 구적이다. 처음 시도한 "분위수 공간 (0,1)을 균일 절점으로 적분"은 끝점 특이성 때문에 수렴이 느려(절점 256개로도 1e-6) 버렸고, **통제집단이 작은 불균형 자료에서는 Z0 방향 해상도가 모자라** 구간 분할을 쓴다. 표본 크기가 같은 비교 집단은 한 번만 계산하고 거듭제곱한다(균형이면 빠름). 20집단×5만 건이 약 2초. 기준값 `gen_reference_anova.py`의 Dunnett은 scipy.integrate.quad 기반이고 scipy.stats.dunnett(준-몬테카를로)은 유의확률 약 5e-5, 신뢰구간 약 1e-3 오차라 보조 대조로만 쓴다(99% 신뢰구간은 scipy가 수렴 경고를 내서 95%만 비교). Dunnett 평균차이는 (집단 − 통제)라 같은 쌍의 LSD(통제 − 집단)와 부호가 반대다.
- **Kaplan–Meier(0.42.0)**: 이름 접두어 `sv`(`Stats_Kmeans.js`의 `km*`와 겹치지 않도록; 분석 키만 `km`). 역할 키 `time`, `event`, `group`(`testdata.test.js`의 요청 키 목록에 추가). 생존함수는 `svKm`(사건 시점 배열 tt·nr·dd·S·se·lo·hi), 백분위는 `svQuantile`(≤ 기준, 오차 1e-12; lifelines와 같고 statsmodels `quantile`은 엄격 부등호라 정확히 같은 수준에서만 다르다), 비교는 `svCompare`(가중치 3종을 한 번에 누적, 분산이 0인 집단은 빼고 자유도 감소). 쌍별은 같은 함수에 집단 두 개를 넘긴다. 제한 평균은 가장 큰 관측 시간까지(표준오차 없음). 기준값 생성 `gen_reference_km.py`는 statsmodels·lifelines(개발용, py -3.12) 필요. lifelines `qth_survival_times`의 q는 **생존율 수준**(S ≤ q)이라 백분위 p에는 1−p를 넣는다. 정확히 같은 수준(동률)에서는 lifelines가 부동소수점 잡음으로 다음 시점을 고를 수 있어 테스트가 동률을 따로 처리한다.
- **검정력·표본 크기(0.41.0)**: 분석 정의의 `noData: true`(client.html)와 `analysisNeedsData_`(Api.js)는 **같은 키 목록(power)** 을 가져야 한다. 분석 창은 `noData`이면 역할 칸 대신 안내 문구를 보이고(`renderSetup`), 변수 목록 패널은 그대로 둔다. `gen_test_datasets.js`의 `NO_DATA` 목록이 "시험 데이터 항목이 필요하다"는 규칙의 예외이고 `TestData.js`에 `TEST_NO_DATA_`로 나간다(`testdata.test.js`가 client.html에 있는 키인지 확인). 계산: 독립·대응 t는 `pnct`(정확), 분산분석·회귀는 `pncf`(λ = f²N, 분산분석 N = k·n), 상관은 **pingouin `power_corr`와 같은 Fisher z 보정판**(임계 r_c = √(t²/(t²+N−2)), z_r = atanh r + r/(2(N−1)); 순수 Fisher z보다 정확 분포에 가까워 이 식으로 정함, 사용자와 합의한 "Fisher z 근사"의 구현 방식), 비율은 Cohen h의 정규 근사. 표본 크기는 지수 확장 + 이분 탐색(최대 100만, 넘으면 오류), 효과크기는 이분법. `n2 = ⌈집단 크기 비 × n1⌉`. **statsmodels `FTestPower`는 df_num과 df_denom의 뜻이 서로 바뀌어 있어**(내부 `ftest_power(effect_size, df2, df1)`) 기준값 생성 때 인자를 바꿔 넣었다. scipy `nct`는 비중심도가 매우 크면 NaN을 돌려줘 그런 행은 기준값에서 뺐다. 옵션 키: `test`, `solve`, `effect`, `alpha`, `power`, `n`, `k`, `u`, `p1`, `p2`, `tails`, `ratio`, `dropout`.
- **편상관(0.40.0)**: `runCorrelation`이 `request.controls`가 비어 있지 않으면 `runPartialCorrelation_`로 분기(기존 경로는 그대로). `partialCorrelation(varCols, ctrlCols, conf)`: 열을 평균 0·길이 1로 맞춘 상관행렬 R, Σ = R_vv − R_vz R_zz⁻¹ R_zv, r = Σ_ij/√(Σ_ii Σ_jj). 통제변수 상관행렬이 양정치가 아니면(선형결합) 오류, 분산 0이면 오류, Σ_ii ≤ 1e-12(통제변수로 완전히 설명)이면 그 변수의 편상관은 null(표에는 NaN). 스피어만은 `rankAverage_`로 모든 열을 순위로 바꾼 뒤 같은 계산(pingouin과 같은 방식). 잔차 산점도는 `olsFit`의 `resid`. 클라이언트의 `listwise` 체크박스 기본이 false라 "무시한다" 경고를 내면 항상 보이므로 경고는 없고 표 각주에만 적었다. pingouin의 신뢰구간은 6자리로 반올림된 값이라 기준값 비교 허용오차를 둠.
- **서열 로지스틱(0.39.0)**: 모수 φ = [β(표준화 척도), θ(문턱값)], 문턱값은 오름차순 유지(`θ_{j+1} − θ_j > 1e-9`) 아래 뉴턴-랩슨. 로그가능도 Σ log(F(θ_c − η) − F(θ_{c−1} − η)), 기울기·헤세는 `olEval_`의 해석식(η, θ_c, θ_{c−1} 세 변수 블록을 사례마다 누적). 헤세는 β–β 아래삼각 + θ–β + θ–θ 로 채우고 마지막에 대칭화. 표준화 → 원래 척도 변환은 선형 `A` 행렬로 공분산까지 옮김. 수렴 판정 `maxΔ < 1e-9` & `ΔLL < 1e-11(1+|LL|)`, 최대 100회. **statsmodels `OrderedModel`의 문턱값 SE는 delta 방법으로 변환해 대조**(모수 공간이 [β, 첫 문턱값, log 증분]). **Brant**: 문턱값마다 `logisticFit`(Y > j)을 적합하고 V_ml = cov_m (X'diag(π_l(1−π_m))X) cov_l (m ≤ l)로 계수 사이 공분산, 차이 대비 Wald (omnibus df = k(J−2), 변수별 df = J−2). 문턱값 하나라도 분리·미수렴이면 Brant 전체를 계산하지 않고 경고(`ologit-?` 기준값의 2번 자료가 이 경우). **Brant 통계량은 식만 확인**(계수·공분산 구성요소는 statsmodels Logit으로 독립 확인), SPSS의 평행선 검정(우도비)과는 방식이 달라 값이 다름. 사례 5만 × 변수 10 × 범주 10 최악 경우 Node 약 6초(Brant가 대부분; x x' 위삼각을 미리 packing해 줄임). 요청 키 `dependent`, `covariates`, `factors`, 옵션 `parallel`(false가 아니면 Brant), `classify`, `save`(예측범주 + 확률_범주값 열 J개), `lastRef`, `conf`.
- **평가자 일치도(0.38.0)**: kappa와 ICC는 사용자 결정으로 **두 항목**(`kappa`, `icc`)이고 모두 변수 여러 개 = 평가자 열. kappa는 변수 2개면 Cohen, 3개 이상이면 **자동으로 Fleiss**. 범주 = 모든 평가자 값의 합집합(값 순, ≤20), 가중 kappa의 거리는 범주 **순서 위치**(값 크기 순) 기준 선형 |i−j|/(r−1) 또는 이차 — sklearn·statsmodels와 같은 정의. Cohen 표준오차는 Fleiss·Cohen·Everitt(1969) 비영가설 식(신뢰구간), 영가설 표준오차로 z(SPSS의 근사 T와 같음). **Fleiss kappa의 표준오차·z는 Fleiss(1971) 식이며 다른 도구로 대조하지 못했다**(kappa 값은 statsmodels와 일치, 범주별 가중평균 항등식으로 내부 확인). ICC 6유형은 McGraw & Wong / pingouin 식(신뢰수준만 일반화)이고 pingouin 대조는 95%만 가능(90%는 같은 식). ICC 해석에서 굵게 표시한 행은 ICC(2,1)·ICC(3,1). 옵션 `weights`('none'|'linear'|'quadratic'), ICC 옵션 `anova`(서버에서 `false`가 아니면 표시; 분석 창에 기본 옵션이 하나 이상 있어야 한다는 client_meta 규칙 때문에 둠).
- **혼합 설계(0.37.0)**: 집단변수는 `rmanova`의 선택 역할 `factor`(비면 일원 반복측정 경로, `runRepeatedAnova`가 `runMixedAnova_`로 분기). 개체-간 SS는 사람별 평균×√k(SPSS의 평균 변환과 같은 척도). 시간 효과는 대비 점수 절편의 **비가중 평균 검정**(유형 III)이라 집단 크기가 달라도 SPSS와 맞는다. 구형성 검정·ε는 집단 안에서 합친 공분산(자유도 N−g), pingouin `mixed_anova`의 W·p·ε와 균형 자료에서 일치. **HF ε = ((N−g+1)pε−2)/(p(N−g−pε))(Lecoutre; R car와 같다고 알려짐)**는 집단이 2개 이상일 때 numpy 식 외에 대조 도구가 없다(단일 집단이면 기존 식과 같음을 테스트). 단순 효과는 집단별로 따로 반복측정 ANOVA(그 집단 오차항)와 측정별 일원 ANOVA(등분산 가정)이고 SPSS EMMEANS의 풀링 오차항 방식과 다를 수 있다. 일반화 η²는 혼합 설계에서 정의가 갈려 표시하지 않는다. 쌍별 비교는 집단 안에서 측정 쌍마다. `xTicks`로 상호작용 그림에 측정 이름 표시.
- **이원 분산분석(0.36.0)**: 제곱합은 효과(합 0) 코딩의 축소·전체 모형 잔차제곱합 차이(유형 III: 항 하나를 뺀 모형, 유형 II: 주효과는 다른 주효과만 있는 모형과 비교). 설계가 범주형이라 모든 모형의 SSE = 셀 안 제곱합 + Σ n_ij (셀 평균 − 적합값)² 이므로 **셀 평균(a×b개)의 가중 최소제곱**으로 계산한다(사례 단위 QR은 10×10 × 10만 건에서 10초가 넘어 바꿨다). 절편(유형 III) SS = μ̄²(ab)²/Σ(1/n_ij) (SPSS 절편 행, 유형 II에서는 생략). 사후검정은 SPSS처럼 **관측 주변평균** 비교 + 이원 모형의 MSE·오차 자유도, Tukey-Kramer. 추정 주변평균은 셀 평균의 비가중 평균(SE = √(MSE Σ1/n_ij)/개수). **단순 주효과** = 한 요인의 각 수준에서 다른 요인 효과, SS = Σ n_ij(셀 평균 − 그 수준 가중평균)², F = (SS/df)/MSE(이원), SPSS EMMEANS COMPARE와 같은 검정. 모든 셀에 사례가 있어야 하며 비면 어느 조합인지 오류. 요청 키 `dependent`, `factor1`, `factor2`, 옵션 `ss`('III'|'II'), `posthoc`('tukey'|'bonferroni'|'none'), `levene`·`plot`·`simple`(서버에서 `false`가 아니면 켬), `emmeans`. 선 그래프의 `xTicks`는 `Charts.js`의 선택 인자(`renderLine_`만 지원).
- **요인분석 2단계(0.35.0)**: **프로맥스는 Kaiser 정규화 방식**(행을 길이 1로 맞춰 베리맥스 → 목표 |x|^(κ−1)에 최소제곱 → 열 정규화 → 행 길이 복원)이고 factor_analyzer `Rotator(method='promax')`·SPSS와 같다. R의 `stats::promax`는 정규화하지 않아 값이 다르고(0.003 정도), statsmodels의 promax는 R·Stata와도 다르다고 문서에 적혀 있다. 요인 상관 Φ = (U'U)⁻¹, 구조 행렬 S = PΦ, 공통성 diag(PΦP')가 보존된다. 정렬·부호는 패턴 행렬의 열 제곱합 기준(Φ에도 같이 적용). 사각 회전에서는 회전 제곱합 열을 표시하지 않는다(SPSS의 oblique 합계 계산 방식을 확인하지 못해 비워 둠). **병렬분석**: 표준정규 난수 n×p 자료의 상관행렬 고유값(Jacobi) 평균·95백분위, `mulberry32_`(Stats_Mediation.js) + Box–Muller, 시드 기본 2026, 모의 횟수 = clamp(3e7/(n·p²/2), 20, 100), 권하는 수 = 앞에서부터 실제 고유값 > 95백분위인 개수. 난수 기반이라 numpy 모의(4,000회)와는 허용오차로만 비교(평균 0.03, 95백분위 0.06). 옵션 `parallel`은 서버에서 truthy일 때만 동작(클라이언트 기본 켬). **요인 점수**: 회귀 방법 Z·R⁻¹·S (직각·회전 없음은 S = 적재 행렬, 프로맥스는 구조 행렬), `saveColumns`로 `Api.js`가 저장(분석 창이 `save` 옵션에 대해 확인창을 띄움). `gas_sim` 시뮬레이션의 시트 모형은 `getMaxColumns`가 없어 `save: true` 요청을 넣을 수 없다.
- **위계적 회귀**: 단계마다 변수를 누적해 `olsFit`을 따로 적합하고 변화 F = ((SSE_이전 − SSE_현재)/추가 계수 수)/(SSE_현재/현재 잔차 자유도). 1단계 변화량은 모형 전체의 R², F (SPSS와 같음). 명목 척도는 더미(`regDummies_`, 기준 첫 범주), 숫자·서열은 숫자 점수 (사용자 결정, 결과 각주에 안내). 2~4단계는 앞에서부터 채워야 하며(건너뛰면 오류) 모든 단계 변수 기준으로 결측 사례를 한 번에 제외. 요청 키는 `dependent`, `block1`~`block4`.
- **Friedman 사후비교**: Dunn–Bonferroni, 동순위 보정 분산 사용 (`friedmanPairs`).
- **효과크기**: Cohen d의 신뢰구간은 비중심 t 분포 정확법(`pnct`, AS 243 급수; df > 4e5 또는 |ncp| > 약 37.6이면 정규 근사). 클라이언트 옵션 기본 켬.
- **변수 계산**: 결과는 `데이터` 탭 맨 오른쪽 새 열 + `변수정의` 등록. 범위 밖 값은 결측 처리 + 경고, 역코딩한 변수에는 값 레이블을 옮기지 않음. `buildDataset`이 사례의 시트 행 번호(`rowNumbers`)를 돌려준다(빈 행 정렬용).
- **예제 데이터**: `Sample.js` 한 곳에서 만들어 시트 채우기·미리보기·테스트가 같이 쓴다. 앞 다섯 열은 처음 예제와 값이 같아야 한다(기준 결과가 의존) — 바꾸면 `tests/sample.test.js`가 실패한다. 뒤의 열은 별도 난수열이라 열을 더 붙여도 앞 값은 변하지 않는다.
- **템플릿 시트 만들기**: 기존 `데이터`·`변수정의` 내용을 지운다(정확한 경고문 `templateWarning_`). 도구 안의 되돌리기는 만들지 않고 파일 > 버전 기록 > 버전 기록 보기로 안내 (개발계획 8-13: 임시 탭 방식은 시트 용량·권한·복잡도 대비 이득이 작다고 판단).
- **표 행 강조**: 결과 행의 `_bold: true` (화면은 `tr.strong`, 내보내기는 굵은 글씨). 문서는 [설계-결과객체.md](설계-결과객체.md).
- **AI 기능**: 위 3번 2항. 원자료 비전송, 키 없이 사용 가능, 사본에서 구현.

- **점검 절차서 관리 (사용자 요청)**: [확인사항.md](확인사항.md)는 시트에서 직접 확인하는 절차의 **최종 문서**이다. 이미 확인된 기능도 **수행 방법과 기대 결과를 지우지 않고** 계속 관리한다. 새 기능을 만들면 항목(ID, 준비, 수행 방법, 기대 결과, 확인 이력)을 추가하고 상태 요약표를 갱신한다(⬜). 기능을 바꾸면 해당 항목의 절차·기대값을 고치고 ⚠로 돌린다. **사용자가 확인했다고 말하지 않은 항목을 ✅로 바꾸지 않는다.**
- **새 통계기법을 고를 때의 한계선 (사용자 방침)**: ① Apps Script 안에서 안전하게 돌아가야 하고(6분 한도, 작은 행렬·짧은 반복, 최대 사례 수에서 Node 기준 10초 안쪽) ② 독립 기준값으로 검증할 수 있어야 하며 ③ 연구에서 자주 쓰이고 꼭 필요한 것을 먼저 하고 나머지는 순서를 뒤로 미룬다 ④ 화면을 복잡하게 하지 않는다. 우선순위와 "하지 않을 것" 목록은 개발계획 8-14.
- **새 기법을 만들 때 시험 데이터를 반드시 함께 만든다**: ① `tests/gen_reference_*.py`가 만든 기준값 JSON에 자료와 기대값이 들어 있게 한다 ② `tests/gen_test_datasets.js`에 그 기법의 항목(자료, 변수정의, 요청, 안내, 기대값)을 추가한다 ③ `node tests/gen_test_datasets.js`로 `src/TestData.js`를 다시 만든다 ④ `tests/testdata.test.js`가 모든 분석에 항목이 있는지, 기대값이 도구의 계산과 같은지 자동으로 확인한다 ⑤ 점검 절차서에 새 항목을 추가한다.
- **분석을 추가할 때 건드리는 곳**: `src/Stats_*.js`(순수 함수 `run*`), `Api.js`의 `analysisFor_`, `client.html`의 `ANALYSES`(label, group, desc, roles, options), `Advisor.js`(추천 규칙과 `ADVISOR_LABELS_` — 라벨은 client.html과 같아야 함), `tests/testdata.test.js`·`gas_sim.test.js`·`testdata_sim.test.js`의 목록, `tests/gen_test_datasets.js`, 문서(CHANGELOG, 사용안내, README, 개발계획, 인수인계, 점검 절차서), `help.html`, `Config.js` 버전.
- **테스트**: `node --test tests/*.test.js` (Node 24는 글롭 필요). 기준값 생성은 `py -3.12 tests/gen_reference_*.py` (scipy 1.17, numpy, 개발용으로 pingouin·statsmodels 설치됨 — 배포 코드와 무관). 새 분석은 독립 기준값과 대조하는 테스트를 같이 만든다.
- **Apps Script**: `clasp push -f` (사용자가 허락함). 모든 `.js`가 한 전역 범위라 **함수·변수 이름이 파일마다 고유**해야 하고(`xxxDeps_` 패턴), 다른 파일 함수는 호출 시점에 찾는다. `tests/gas_sim.test.js`가 정순·역순 로드와 전역 이름 충돌을 검사한다. 새 `.js`는 자동으로 포함된다.
- **커밋**: 폴더의 `commit.bat`(테스트를 돌린 뒤 변경 파일을 이 컴퓨터의 git에만 커밋, `Stat_Assistant/` 제외; `/notest`로 테스트 생략). 긴 메시지는 `commit_message.txt`(UTF-8)에 적어 두면 그걸 쓴다 (`-F`). 직접 `git commit`을 쓸 때도 메시지를 파일로 만들어 `-F`, 끝에 `Co-Authored-By` 줄. 커밋 뒤 종료 코드, `git log --oneline`, `git status --short`를 확인한 다음에 보고한다. `git add -A` 대신 경로를 지정한다. **원격 연결·push는 하지 않는다.**
- **문서·코드 패치 방식**: 한글·백틱·`\n`이 섞인 긴 수정은 heredoc 대신 Write 도구로 노드 스크립트 파일을 만들어 실행한다 (스크립트는 스크래치패드에). 스크립트에서 `String.replace(정규식, 함수)`를 쓸 때 캡처 그룹이 없으면 `(m, g1)`로 받지 말 것(오프셋 숫자가 문서에 들어간 적 있음), 치환 문자열의 `$1`이 그대로 남는 사고도 있었으니 패치 뒤 `grep '\$1'`과 줄 앞 숫자(`^[0-9]{3,}`)를 확인한다.
- **미리보기**: `node tests/ui/build_preview.js --reverse` → `tests/ui/preview.html` 등 (git 제외). 이 환경의 브라우저 창은 `file://` 열기가 거부되었다(시각 확인은 못 함, 노드 스텁으로 화면 논리를 검증). 실제 시트 서식·권한·표시 지연은 미리보기로 알 수 없다.
- **시트 확인 요청**: 확인 방법과 기대값을 점검 절차서 항목으로 정리해 주고, 사용자가 결과를 알려 주면 반영한다. 안 보이는 동작은 추측으로 고치지 말고 진단부터 넣는다.
- **동작 원칙**: 외부 라이브러리 없이 직접 구현, 분석은 UI와 분리된 순수 함수 `(dataset, request) → 결과 객체`, 개인정보는 익명화 전제, 배포는 시트 복사 템플릿.
