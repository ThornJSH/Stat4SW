# 릴리스 절차 (시트 복사 템플릿)

이 프로젝트는 **개발 시트(로컬 `.clasp.json`이 가리키는 시트, 주소는 `doc/local/개발환경.md`)를 복사해 만든 템플릿**을 배포합니다.
사용자는 템플릿의 "사본 만들기"로 자기 시트를 얻고, 스크립트는 그 사본에 함께 복사됩니다. 별도의 서버, 웹앱 배포, 애드온 심사는 없습니다.

- 개발 시트는 **배포하지 않습니다.** 작업 중인 코드와 예제·결과 탭이 섞여 있기 때문입니다.
- 배포용 템플릿은 릴리스할 때마다 개발 시트를 **새로 복사해서** 만듭니다.
- git은 로컬 전용이라 태그도 로컬에만 있습니다.

## 버전 규칙 (1.0.0 배포 이후)
- `src/`를 고칠 때마다 `APP_VERSION`을 올리고 CHANGELOG에 쓴다: 버그·문구 수정 1.0.x, 기능 추가·동작 변경 1.x.0, 호환이 깨지는 큰 변화 2.0.0. 문서만 고칠 때는 올리지 않는다.
- 커밋 뒤 로컬 태그 `vX.Y.Z`를 단다. 사용자에게 보이는 버전은 메뉴 `정보·저작권`에 표시되므로 배포된 사본이 어느 코드인지 거기서 확인한다.
- 이미 복사된 사본은 자동으로 바뀌지 않는다. 사용자에게 새 버전을 쓰게 하려면 4번 절차대로 새 템플릿을 배포한다 (자잘한 수정은 모아서 배포한다).

## 1. 개발 PC에서 (코드 확정)

1. 테스트가 모두 통과하는지 확인합니다.
   ```
   node --test tests/*.test.js
   ```
2. [확인사항.md](확인사항.md)의 상태 요약표(1번)에 ⬜·⚠가 남아 있지 않은지 보고, 3번의 **릴리스 전 점검 묶음**(빠른 점검 또는 전체 점검)을 수행합니다. 남은 항목이 있으면 릴리스에 영향이 있는지 판단해 기록합니다.
3. 버전을 올립니다.
   - `src/Config.js`의 `APP_VERSION`
   - 루트 [CHANGELOG.md](../CHANGELOG.md)에 이번 버전의 변경 내용
4. Apps Script에 올리고 커밋합니다.
   ```
   clasp push
   git add -A
   git commit -F <메시지 파일>
   git tag vX.Y.Z
   ```
   (커밋 메시지에 큰따옴표가 있으면 PowerShell에서 깨지므로 메시지는 파일로 만들어 `-F`로 씁니다. 커밋 뒤 `git log --oneline`과 `git status --short`로 결과를 확인합니다.)

## 2. 개발 시트에서 (템플릿 만들기)

5. 개발 시트를 엽니다. **메뉴 Stat4SW 통계분석 > 정보·저작권**의 버전이 방금 올린 버전인지 확인합니다 (새로고침 필요할 수 있음).
6. **파일 > 사본 만들기**를 누르고 이름을 `Stat4SW vX.Y.Z (템플릿)`으로 지정합니다. (스크립트도 함께 복사됩니다.)
7. **사본에서** 아래를 비웁니다.
   - `데이터` 탭: 1행을 포함한 모든 내용을 지웁니다 (서식은 남겨도 됩니다).
   - `변수정의` 탭: **2행부터** 지웁니다 (1행의 머리글과 척도 드롭다운은 유지).
   - `결과` 탭: 탭을 삭제합니다 (내보내면 새로 만들어집니다).
   - 그 밖의 탭(예: `시트1`)도 삭제합니다.
8. **사본의** `확장 프로그램 > Apps Script`를 열고 함수 `checkTemplateReady`를 선택해 실행합니다.
   - 처음에는 권한 승인이 필요합니다 (사용자가 겪는 과정과 같습니다. 이때 승인 창의 문구도 확인해 둡니다).
   - **"문제가 없습니다"**가 나오면 통과입니다. 남은 항목이 알림으로 나오면 비우고 다시 실행합니다.
9. 사본에서 한 번 시험합니다: **Stat4SW 통계분석 > 예제 데이터 채우기** → 분석 몇 개 실행 → `시트로 내보내기` → 확인한 뒤 **7번처럼 다시 비우고** 8번을 한 번 더 실행합니다.

## 3. 공유

10. 사본의 **공유**를 `링크가 있는 모든 사용자 — 뷰어`로 설정합니다 (편집 권한을 주지 않습니다). **편집 링크(`/edit`)나 편집자 권한을 주면 사용자들이 같은 시트에서 작업해 데이터가 섞이므로 절대 그렇게 하지 않습니다.** 사용자는 `/copy` 링크로 각자 자기 계정에 사본을 만들고, 데이터는 각자의 사본에만 있습니다 (처음 분석 창을 열 때 "개인 사본" 안내가 한 번 나옵니다).
11. 사용자에게 줄 링크는 주소 끝의 `/edit…`을 `/copy`로 바꾼 것입니다. 열면 바로 "사본 만들기" 화면이 나옵니다.
    ```
    https://docs.google.com/spreadsheets/d/<파일 ID>/copy
    ```
12. 함께 줄 문서: [사용안내.md](사용안내.md). 시트 메뉴 **Stat4SW 통계분석 > 사용 안내**에도 같은 요점이 들어 있습니다.
13. 이전 버전의 템플릿 파일은 지우지 않고 보관합니다 (문제가 생기면 이전 링크로 되돌릴 수 있습니다).

## 4. 이미 쓰는 사람의 업데이트

복사된 시트는 원본과 연결되어 있지 않아서 **자동으로 업데이트되지 않습니다.** 새 버전을 쓰려면:

1. 새 템플릿을 사본 만들기로 복사합니다.
2. 내 시트의 `데이터`·`변수정의` 탭 내용을 새 시트의 같은 탭에 붙여 넣습니다.
3. (선택) 내보낸 `결과` 탭이 필요하면 따로 보관합니다.

## 참고

- **복사본의 권한**: 복사한 시트의 스크립트는 사용자가 처음 실행할 때 본인 계정으로 승인합니다. 소유자(개발자)의 권한이나 사용자 속성(옵션 기억)은 복사되지 않습니다.
- **소유자 노출**: 템플릿 파일의 소유자 이름·이메일이 사용자에게 보일 수 있습니다. 개인 계정을 쓸 때는 의도한 것인지 확인하세요.
- **`clasp create-version` / 배포(deployments)는 쓰지 않습니다.** 컨테이너 바인딩 스크립트를 시트째 복사하는 방식이라 필요하지 않습니다.
- **되돌리기**: 개발 시트에서 잘못 올렸다면 `git checkout <이전 태그> -- src` 후 `clasp push`로 되돌립니다 (로컬 git 기준).
